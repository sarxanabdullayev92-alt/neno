# Карта OSM с живым трекингом мастеров

Инструкция по переносу в FlutterFlow. Весь код в этой папке написан так,
чтобы вы вручную вставили его в FF как Custom Widget / Custom Action /
Custom Function — без правок в сгенерированном коде.

---

## 1. Что уже сделано на сервере (ничего делать не нужно)

Сервер `159.194.254.20`, домен `ugitubelnid.beget.app`.

| Сервис | Адрес | Проверено |
|---|---|---|
| Тайлы карты | `https://ugitubelnid.beget.app/tiles/{z}/{x}/{y}.png` | отдаёт PNG, кэш на диске 4 ГБ |
| Маршруты OSRM | `https://ugitubelnid.beget.app/route/v1/driving/...` | Кремль→Шереметьево = 29.5 км / 33 мин |

**База данных.** Добавлены колонки `latitude`, `longitude`, `city` в `masters`,
`orders`, `profile`; в `masters` ещё `is_online`, `heading`,
`location_updated_at`. Включён Realtime на `masters` и `orders`.
Старые текстовые поля `currentLocation` и `usersLongANDLat` не тронуты.

**Функции в БД** (вызываются из кода):

| Функция | Что делает |
|---|---|
| `nearby_masters(lat, lng, city, radius_km, limit)` | мастера онлайн рядом, с расстоянием |
| `update_master_location(lat, lng, heading, is_online, city)` | мастер шлёт свою позицию |
| `set_master_online(online)` | включить / выключить смену |
| `accept_order(order_id)` | принять заказ, **атомарно** |
| `available_orders(lat, lng, radius_km, limit)` | свободные заказы для мастера |
| `distance_km(lat1, lng1, lat2, lng2)` | расстояние по прямой |

`nearby_masters` не возвращает телефон мастера: он нужен только после
принятия заказа, а функция отвечает в том числе неавторизованному клиенту.

Отдельно починено: у таблиц `masters`, `orders`, `options`, `price`,
`services` **не было автоинкремента `id`** — вставка падала с
`null value in column "id"`. Создать заказ или мастера было невозможно.
Теперь `generated by default as identity`.

Применённые миграции лежат в папке `sql/` — они уже выполнены на сервере,
хранятся как история изменений.

### Что проверено вживую

- тайлы отдаются, кэш на сервере работает (`X-Cache-Status: HIT`)
- OSRM считает реальный маршрут: Кремль → Шереметьево = 29.5 км / 33 мин
- `nearby_masters` возвращает только мастеров на смене, в своём городе,
  в радиусе, со свежей позицией — «протухших» и оффлайн отсекает
- **сквозной тест живого трекинга**: мастер отправил позицию через RPC,
  второй клиент получил её по Realtime за секунды
- `accept_order` при одновременном нажатии двух мастеров отдаёт заказ
  первому, второй получает `order already taken`
- сборка обоих проектов в том виде, как их выгружает FlutterFlow
  (с автоматической шапкой импортов) — без ошибок, после исправления
  конфликта `LatLng` в виджете 13.09.2026

Актуальный список того, что делать сейчас, — в файле `ЧТО_ДЕЛАТЬ.md`.

В базе оставлены 6 демо-мастеров (телефоны `+7900…`). На карте их не
видно: их точки старше 10 минут и отсекаются как устаревшие. Как удалить —
в разделе 8.

## 2. Зависимости — вписать в обоих проектах

FlutterFlow → **Custom Code → Dependencies** → добавить построчно:

```
flutter_map: 8.1.1
latlong2: 0.9.1
geolocator: 14.0.2
```

Версии подобраны под конфликты FlutterFlow, менять не глядя не стоит:

- `flutter_map 8.2+` требует `path_provider ^2.1.5`, а FF пинит `2.1.4` → не соберётся
- `latlong2 0.10.x` несовместим с `flutter_map 8.1.1` (тому нужен `^0.9.1`)
- `geolocator 14.0.3` требует Dart 3.10, в сборке FF — 3.9 → не соберётся

`http` уже есть в обоих проектах.

## 5. Что куда вставлять

### 5.1. Custom Widget — `OsmMapWidget` (оба проекта)

Файл `01_widget_OsmMapWidget.dart`. Параметры и их типы перечислены в
шапке файла. Все — Nullable, кроме `width` / `height`.

Два Callback-параметра заводятся как тип **Action**:
`onMasterTap` (параметр `masterId` типа int),
`onRouteInfo` (один параметр `route` — Double, Is List: [км, минуты]) и
`onCenterChanged` (один параметр `point` — Double, Is List: [широта, долгота]).
Два Double-параметра FlutterFlow путает, поэтому списки.

**Клиент, страница `MapPage`** — карта со всеми мастерами города:

```
autoLoadMasters = true
city            = "Москва"
radiusKm        = 50
maxMasters      = 50
refreshSeconds  = 25
centerLat/Lng   = позиция клиента (из getMyLocation)
```

**Клиент, после принятия заказа** — видно, как мастер едет:

```
autoLoadMasters = false
trackMasterId   = orders.mastersID
clientLat/Lng   = адрес заказа
showRoute       = true
```

**Мастер, страница `WorkMain`** — своя позиция на карте:

```
trackMasterId = свой id из masters
centerLat/Lng = своя позиция (из getMyLocation)
initialZoom   = 14
```

**Мастер, страницы `OrderOffer` и `ActiveOrderDetail`** — маршрут к клиенту:

```
trackMasterId = свой id из masters
clientLat/Lng = координаты заказа
showRoute     = true
```

У мастера используйте `trackMasterId`, а не `meLat` / `meLng`: так точка
и маршрут обновляются сами вместе с передачей позиции. `meLat` задаётся
один раз при открытии страницы и дальше не двигается.

**Выбор адреса** — `pickLocation = true`, координаты приходят в
`onCenterChanged(point)`: point[0] = широта, point[1] = долгота.

Плашка «12,4 км · 23 мин» рисуется виджетом сама. Если те же цифры нужны
в другом месте экрана (карточка «АДРЕС И ДИСТАНЦИЯ») — возьмите их из
callback `onRouteInfo` и положите в Page State, а не запрашивайте заново.

### 5.2. Custom Actions

| Файл | Имя | Проект | Куда вешать |
|---|---|---|---|
| `02_action_getMyLocation.dart` | `getMyLocation` | оба | On Page Load карты |
| `03_action_setMasterTracking.dart` | `setMasterTracking` | master_profi | тумблер «Смена» на `WorkMain` |
| `04_action_acceptOrder.dart` | `acceptOrder` | master_profi | кнопка «ПРИНЯТЬ ЗАКАЗ» на `OrderOffer` |
| `05_action_subscribeNewOrders.dart` | `subscribeNewOrders` | master_profi | On Page Load `WorkMain` |
| `06_action_getRouteInfo.dart` | `getRouteInfo` | оба | где нужны км/минуты без карты |
| `07_action_loadNearbyMasters.dart` | `loadNearbyMasters` | nado_clean | только если нужен список мастеров |
| `09_action_subscribeMyOrder.dart` | `subscribeMyOrder` | nado_clean | On Page Load `MapPage` — узнать, что мастер принял заказ |

Что делать сейчас — в файле `ЧТО_ДЕЛАТЬ.md`.

**Тумблер «Смена»** на `WorkMain`:
- включили → `setMasterTracking(enabled: true, intervalSeconds: 60, city: "Москва", setOnline: true)`
- выключили → `setMasterTracking(enabled: false, ...)`

**Когда мастер принял заказ** — вызвать ещё раз с `intervalSeconds: 15`.
При завершении заказа вернуть `60`. Это и есть экономная схема: частые
обновления только тогда, когда клиент реально смотрит, как вы едете.

**`acceptOrder` возвращает строку**, её надо обработать:
- `"ok"` — заказ ваш, переходим на `ActiveOrderDetail`
- `"taken"` — показать «Заказ уже принят другим мастером»
- `"notmaster"` — пользователь не заведён как мастер
- `"error"` — проблема со связью

### 5.3. Custom Functions

Файл `08_functions.dart` — **три отдельные функции**, каждую заводить
отдельной записью: `distanceKm`, `formatDistance`, `parseCoord`.

`parseCoord` нужна только для старых текстовых полей вида
`"55.751244, 37.618423"`. Для новых записей пользуйтесь числовыми
колонками `latitude` / `longitude`.

## 6. Что нужно писать в базу из приложения

Карта показывает только то, что туда попало.

**Мастер.** Строка в `masters` с `user_profile = текущий auth uid`.
Без неё `update_master_location` и `accept_order` вернут ошибку.
Поля `latitude`, `longitude`, `is_online`, `location_updated_at`
заполняет `setMasterTracking` сам.

Порядок при регистрации мастера важен: **сначала строка в `profile`,
потом в `masters`**. У `masters.user_profile` стоит внешний ключ на
`profile.id`, и попытка создать мастера раньше профиля падает с
`violates foreign key constraint "masters_user_profile_fkey"`.

**Заказ.** При создании заказа обязательно заполнять `latitude`,
`longitude`, `city`, `address` — иначе мастер не увидит ни расстояния,
ни маршрута. Координаты брать со страницы `SearchingForAddress`.

## 7. Ограничения, о которых стоит знать

**Трекинг работает, пока приложение открыто.** Таймер живёт в процессе
приложения. Если мастер свернёт приложение надолго или система выгрузит
процесс — передача позиции остановится, и через 10 минут мастер пропадёт
с карты клиента (это защита от «призраков», отсечка по
`location_updated_at`). Для передачи позиции при выключенном экране нужен
foreground-сервис с постоянным уведомлением — отдельная задача,
на Android без него никак.

**OSRM собран на Москву и область** (bbox 35.1–40.3° в.д., 54.2–56.96° с.ш.).
Внутри — реальные маршруты по дорогам. За пределами области маршрут не
построится, останутся только маркеры. Расширение — в разделе 8.

**Открытый доступ к данным.** Сейчас политики RLS такие, что любой
авторизованный пользователь может читать, менять и удалять **любые**
заказы и профили — включая чужие. Это досталось от изначальной настройки
FlutterFlow, я это не трогал, чтобы не сломать работающее приложение.
Перед выпуском в прод это надо закрыть — скажите, и я подготовлю
политики отдельно.

## 8. Обслуживание сервера

**Расширить регион маршрутов** (например, добавить Санкт-Петербург):

```bash
ssh -i ~/.ssh/nado_clean root@159.194.254.20
cd /opt/osrm
# заменить bbox на нужный или взять весь ЦФО (central.osm.pbf уже скачан)
osmium extract --bbox 29.0,54.2,40.3,60.2 central.osm.pbf -o moscow_region.osm.pbf --overwrite
./build.sh          # 10-15 минут
docker restart osrm
```

Файл `central.osm.pbf` (876 МБ, весь Центральный ФО) лежит на сервере.
Санкт-Петербурга в нём нет — для него нужен `northwestern-fed-district`
с Geofabrik.

**Посмотреть, работает ли кэш тайлов:**

```bash
curl -sI https://ugitubelnid.beget.app/tiles/12/2474/1283.png | grep X-Cache-Status
# HIT — отдано из кэша, MISS — скачано с openstreetmap.org
```

**Удалить тестовых мастеров:**

```sql
delete from masters where phonenumber like '+7900%';
```

**Бэкап схемы** перед изменениями лежит в `/root/backups/` на сервере.
